[09/09/2026 22:10] commit 3b09e94 - juannifato
Mensaje: feat: conectar el extractor a la API real de Aerolineas Argentinas

Identificada la API que usa la propia web de Aerolineas para mostrar
vuelos en millas: GET api.aerolineas.com.ar/v1/flights/offers. Un
sondeo sin credenciales devuelve 401 y no 404, lo que confirma que
la ruta y los parametros son correctos y que solo falta el token.

El extractor arma la consulta con el formato que espera la API: los
tramos van como ORIGEN-DESTINO-AAAAMMDD en el parametro leg, que se
repite para la vuelta, y awardBooking=true es lo que convierte la
busqueda en busqueda por millas. Verificado con una prueba que
intercepta la peticion y comprueba la URL resultante sin llegar a
enviarla, para no consultar el servidor de Aerolineas al azar.

La API exige un token Bearer que no sale de un endpoint publico
(/v1/token responde 404), asi que se lee de AEROLINEAS_TOKEN en el
.env, igual que la clave de Groq. Cuando falta o vence, el backend
lo dice con un motivo propio en lugar de fallar de forma opaca.

POST /buscar ahora acepta fecha_vuelta y adultos, ambos opcionales,
y valida que la vuelta no sea anterior a la ida y que los pasajeros
esten entre 1 y 9. Los codigos HTTP pasan a distinguir de quien es
el problema: 400 si los datos que llegaron estan mal, 503 si al
backend le falta configuracion y 502 si fallo la aerolinea.

Probado con 16 casos entre construccion de URL y endpoint.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>

Se integró el extractor con la API real de Aerolíneas Argentinas, armando la URL con los parámetros `leg` y `awardBooking=true` y leyendo el token Bearer desde la variable `AEROLINEAS_TOKEN` del .env. Además, el endpoint `POST /buscar` ahora acepta `fecha_vuelta` y `adultos` como opcionales, con validaciones que impiden fechas de regreso anteriores a la ida y limitan la cantidad de pasajeros entre 1 y 9, devolviendo códigos HTTP específicos (400, 502, 503) según el tipo de error. También se añadieron configuraciones y mejoras en la clase base del scraper y se actualizó la documentación de entorno.

[10/09/2026 20:04] commit 8b08281 - juannifato
Mensaje: Construir el cerebro analitico de la Fase 4 y automatizar el token

Se agrega el paquete ia/ con dos piezas separadas a proposito. El modulo
recorte.py achica la respuesta de la aerolinea a lo unico comparable, porque el
74% del crudo (fareRules y combinableOffers) es ruido que haria la consulta a la
IA lenta, cara y menos precisa; ademas le pone a cada tarifa un id estable. El
modulo analisis_ia.py le pasa ese recorte a Groq para que elija un id por tramo,
y despues Python reconstruye la respuesta desde el recorte en vez de confiar en
que el modelo copie bien las millas; si la IA falla o elige un id inexistente,
cae a la regla de menos millas y lo avisa. El endpoint /buscar ya devuelve la
recomendacion masticada en lugar del crudo. Se suman tests, dos sin red y uno
que pega contra Groq de verdad.

Se deja escrita la renovacion automatica del token de Aerolineas, que sale de
POST /v1/auth/token con un client_secret que Juan tiene que cargar, para no
pegarlo a mano cada 24 horas. Queda sin enganchar al flujo hasta poder probarlo.

De paso se corrige la bitacora, que truncaba los resumenes porque gpt-oss gasta
tokens razonando: se sube max_tokens y se agrega reasoning_effort bajo, el mismo
arreglo que ya se habia hecho en el resto del proyecto.

Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>

Se añadió el paquete ia/ con los módulos recorte.py y analisis_ia.py para reducir la respuesta cruda de la aerolínea a los datos esenciales, asignar IDs estables a cada tarifa y delegar la selección de la mejor opción a Groq, reconstruyendo luego la respuesta completa y garantizando un fallback a la regla de menos millas. Además, se implementó la lógica de renovación automática del token de Aerolíneas (renovar_token.py y actualización en token_aerolineas.py) y se adaptó el endpoint /buscar para devolver la recomendación procesada; se añadieron tests unitarios y de integración, y se ajustaron configuraciones de token y logging.
